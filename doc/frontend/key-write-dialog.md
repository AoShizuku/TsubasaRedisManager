# 新建与克隆对话框

覆盖：`src/components/dialogs/KeyWriteDialog.vue`、`src/components/dialogs/KeyBytesInput.vue`、`src/lib/keyCreation.ts`、`src/stores/clones.ts`、`src/stores/ui.ts`（`openCreateKey`、`openCloneKey`）、`src/styles/keywrite.css`、`src/components/shell/StatusBar.vue`（「克隆任务」菜单）

六种类型的新建，以及单 Key 克隆：同 DB、跨 DB、跨连接。集群只有 db0，但源与目标可以在
不同槽位、不同节点，也可以在单机与集群之间复制。后端那一半——创建原子性、DUMP/RESTORE 传输、
跨服务器 TTL、克隆任务的状态与取消——见 [backend/key-write](../backend/key-write.md)。

## 入口

| 入口 | 行为 |
|---|---|
| DB 右键 → 新建 Key… | 使用该 DB，尚未打开时先建立会话（`KeyTree.vue` 的 `createInDb`） |
| namespace 右键 → 在此前缀下新建 Key… | 预填字面前缀与连接分隔符，光标置末尾 |
| Key 浏览器工具栏 / 空状态 / 右键菜单 | 在浏览器所属 DB 新建，**不从 MATCH 猜前缀** |
| 树、精确命中行、浏览器数据行右键 → 克隆 Key… | 固定源 Key，目标默认当前 DB |
| Key 详情 → 更多 → 克隆 Key… | 复制执行时的服务端数据，不包含未保存的编辑 |
| 状态栏「克隆任务」→ 某一项 | 带 `taskId` 重开对话框，表单恢复成那次提交的目标，显示任务结果 |

侧栏的 `+` 是新建连接，标签栏的 `+` 是新建标签页，都不是新建 Key。
「复制 Key 名」只操作剪贴板，与「克隆 Key」是两个菜单项。

## 对话框

`KeyWriteDialog.vue` 一个组件承载两种动作，共用目标数据库、名称、TTL、提交状态，按 `mode` 切换内容。

外观与 [batch](batch.md) 的批量对话框**同一个骨架**，不另起一套——它们是同一类东西，从模态里发起的写操作：
标题下写「连接 / dbN」，正文用 `.form-sec` + `.cap` 分节（来源 / 目标 / 初始内容 / 过期时间），字段走 `.field`，
说明走 `.field-hint`，失败与只读走 `.banner-danger`，页脚左侧先说「同名时停止」再放按钮。

源 Key 的类型复用元信息头的 `TypeChip`。这是类型色三处出现之外**唯一的补充**：克隆来源只有一个 key，
不会退化成色块墙；数据表格内部仍不上类型色。

### 名称与字节

- **Key 名不 trim、不做 glob 转义。** 空格与空字符串都是合法 Key 名；名称为空时显示明确提示，而不是拒绝。
- 每个值、字段、成员**各自**选 UTF-8 / Base64（`KeyBytesInput.vue`）。格式开关是挂在输入格右上角的 chip
  而不是下拉：一行 hash 是「字段 + 值」两格，每格再挂一个下拉，一行就散了。
- 切换格式时转换的是**原字节**；非 UTF-8 的字节不允许转成文本（`TextDecoder` 的 `fatal`），
  否则切过去再切回来就是另一份数据。写入参数一律是 base64 字节，见
  [backend/ipc-contract](../backend/ipc-contract.md)「写入参数是字节」。

### 初始内容

- 新建默认 STRING、不过期。STRING 可以为空；HASH / LIST / SET / ZSET 至少一行；
  STREAM 输入第一条消息的字段和值，ID 由服务端生成。
- Hash 字段、Set 与 ZSet 成员**按原始字节判重**（前端比较的是规范化后的 base64）；
  List 保留顺序与重复项；Stream 字段不判重。
- ZSet 的 score 接受有限数字与 `±inf`。
- 行数上限由前端（添加按钮、`initialValue`）与后端同时拦；总字节上限**只由后端拦**。
  两个数以 `key_write.rs` 的 `MAX_ROWS`、`MAX_INITIAL_BYTES` 为准，前端的 256 是同一个数的副本。

### 克隆的目标与过期时间

- 同连接同 DB 时名称建议 `原名_copy`，换到其他 DB / 连接时建议原名。**用户手改过的名称不被建议值覆盖**：
  只有当前名称仍等于旧建议时才换成新建议。
- 切换目标连接时，DB 回到源 DB（同一连接）或 0。目标是集群时 DB 锁定为 0。
- 默认**保留到期时刻**，也可以选永久或自定义相对 / 绝对时间。勾选项的文案按是否同连接区分：
  同连接是「保留源 Key 的到期时刻」，跨连接是「保留剩余有效期，扣除传输耗时」——后者正是
  [backend/key-write](../backend/key-write.md)「跨服务器 TTL」的语义。
- TTL 选择器不显示 `PERSIST` / `EXPIRE` 命令提示（`hide-command-hints`）：TTL 与内容在同一个脚本里落地，
  单独列一条命令名会让人以为会多发一条。
- **源只读不阻止克隆**——读源不需要写权限。**目标只读以实际目标会话的 `readonly` 为准**，不从连接配置推断；
  目标会话尚未打开时，提交时先 `openDb` 再判。见 [backend/sessions](../backend/sessions.md)「只读属于会话」。
- **脚本能力同理。** 新建是目标上的一个脚本，克隆的快照在源上、恢复在目标上，所以新建查目标、克隆查两端的
  能力 `scripting`；不可用时横幅原样显示后端的 `reason`、提交按钮置灰。目标会话尚未打开时查不到，
  由后端入口的同一条守卫拦。见 [backend/capabilities](../backend/capabilities.md)「功能入口守卫」。

## 提交与结果

**始终不覆盖。** 同名时保留全部输入，页脚换成「打开已有 Key」。

| | 新建 | 克隆 |
|---|---|---|
| 提交中 | 禁用输入，**不能关闭**（`busy`） | 任务启动后禁用输入，**允许关闭**，按钮变成「后台运行」，任务继续 |
| 成功 | 打开驻留页（`preview: false`） | 默认打开副本（「打开副本」可取消勾选）；对话框还开着就自动关闭 |
| 取消 | — | 「停止克隆」；进入 `restoring` 后禁用 |

成功后的刷新两者相同：通知目标会话的 keyspace 更新（`invalidateKeyspace`），浏览器重扫；
侧栏处于搜索 / 作用域 / 模式状态时保留条件重新扫描，并提示按完整 Key 名搜索，否则直接补入新 Key
（`rememberKey`）；DB 计数重新读取（`loadDbList`）。

**写入已成功但后续界面更新失败时明确说出来**（「Key 已写入，但界面刷新失败」），并锁住提交（`written`），
不让用户再写一次。

### 结果待确认

通信超时或中断时，写入可能已经完成。这时**禁止直接再次提交**（`uncertain`），页脚提供「检查目标 Key」：

- 克隆的「待确认」来自后端的 `uncertain` 终态。新建不是任务，由前端判：写请求已经发出，
  而错误不是服务端的明确拒绝、看起来是通信故障（`submit` 里的分类）。
- 核对走独立的只读命令 `redis_key_exists`（严格 `EXISTS`），ACL / 通信错误照实报错。
  **不拿元信息接口里可选字段的降级值当「不存在」**——那里被 ACL 挡掉的一格读成空，与「不存在」分不开。
- **存在只说明当前存在**，不据此宣称上一次操作成功：可能是别人刚好写了同名 key。界面只说「已存在，请打开检查」。
- 确认不存在后允许重试。先前那次请求若稍后才落地，服务端的同名保护仍会挡住覆盖。

## 克隆结果的消费

`stores/clones.ts` **独立于对话框的生命周期**：对话框关掉之后，任务结束时仍由它刷新目标、
按提交时的「打开副本」选择打开副本、发通知。

- **两路来源**：`redis://task-progress` 的 `clone` 条目，加上低频的 `redis_get_clone_task` 轮询兜底。
  事件可能丢失，也可能在 `startCloneKey` 返回、订阅建立之前就已经发出。轮询失败不臆断任务失败，下次再查。
- **去重**：同一任务只 `track` 一次；阶段按 `order` 单调前进，**迟到的旧阶段不覆盖新状态**；
  终态只处理一次（`finish` 之后不再接收），所以后台成功只刷新一次、只通知一次。
- 轮询到的状态同样写回 `tasks` store 的任务摘要。只有事件更新摘要的话，事件丢失时状态栏会留下一个
  「永远运行中」的克隆。
- 状态栏的「克隆任务」菜单列出最近的终态记录（进行中的不裁剪，条数以 `finish` 里的裁剪为准），
  包括已关闭对话框的任务，点开即重开对话框。**这些记录属于本次应用运行，不是持久化的任务历史。**

## 不做

- **覆盖已有 Key。** 新建与克隆都不带覆盖选项，同名一律停止，见 [backend/key-write](../backend/key-write.md)「不做」。
- **从 Key 浏览器的 MATCH 模式猜前缀。** MATCH 是 glob，`user:*:profile` 推不出一个字面前缀；
  猜错了预填进去，用户还得先删掉。
- **结果待确认时自动重试。** 重试撞上同名保护会回一个「已存在」，把「不知道写没写」变成一个看起来确定、
  其实无法判断来源的冲突。核对交给用户显式点击。
- **格式开关做成下拉**，见「名称与字节」。
