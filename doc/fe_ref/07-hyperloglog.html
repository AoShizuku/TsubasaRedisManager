设计要点
  • 子形态而非第七种类型：TYPE 返回的就是 string，树与标签页的圆点、元信息头的徽标一律沿用 STRING 的中性灰，仅加一枚中性 tag「HyperLogLog」。识别在打开 key 时完成：redis_get_key_meta 第二批 pipeline 顺带 GETRANGE key 0 15 校验 HYLL 头，零额外往返；SCAN 不识别（为罕见子形态给全部 string 翻倍探测成本，不划算）。
  • 结构查看器是一个组件的两种排布：健康态 = 底部抽屉（真实实现默认收起），解析为主、原始为辅；损坏态 = 顶到主体，原始为主、banner 说明、解析降级为逐字段 ✓/✗（头部往往还是好的，坏的只是长度或操作码）。「校验失败」不是孤立页面，是同一查看器的退化档位。
  • 热力图是寄存器区的本体表示，不是彩蛋：一寄存器一像素（128 × 128）、灰度、0 为纯黑，均匀噪点即健康，色块与条纹是损坏的形状。服务端对 dense 只校验总长度——长度合法而寄存器是垃圾的 HLL 不会报错，只会安静给错数，这类损坏唯有热力图能显形。sparse 由后端展开成同一个 16,384 数组后同样适用。canvas 原生绘制，零依赖。解说词按非零率分档：低于一成时画面以纯黑为主是常态，换用「亮点 = 被命中的寄存器」的低基数解说，「大块纯色是损坏」那套噪点语法只在高填充时展示——否则健康的小 HLL 会被读成坏的；「平均」低填充时不显示（四舍五入成 0.0 没有信息量）。6-bit 跨界示意只对 dense 成立（sparse 的字节是操作码流），只在 dense 显示。
  • 后端一条读命令 redis_inspect_hll：Rust 解析头部并把寄存器展开为规范数组返回——6-bit 解包与 sparse 的 ZERO/XZERO/VAL 操作码是 Redis 实现知识，按 doc/architecture.md「前后端分层」归 Rust。原始字节走现有 redis_get_string_value（dense 12,304 B 低于 64 KiB 截断线，天然完整）。
  • 染色是专用图例色（魔数 / encoding / 保留 / 基数缓存四色），不动 Redis 类型色；hex 里的底色与字段表的色块同色对照。BIN 不做整列——bit 级信息只在两处承重：基数缓存的最高位失效标记（字段表里单独标出）、6-bit 与字节边界的错位（寄存器区旁的三字节小示意图）。
  • PFCOUNT 的副作用写在状态行上：它会刷新头部 8 字节基数缓存——物理字节可能变化，逻辑值不变。ACL 归类 @read，只读会话照常计数，PFADD 才受只读约束。「只读会话：可计数，不可添加」的角标只在只读会话渲染——对可写会话陈述「不可添加」是假命题，本页 mock 的是可写会话所以没有它。PFMERGE 不进界面：跨 key、集群受 CROSSSLOT 约束、低频，CLI 是正当入口。
  • 大数字 32px 在 tokens 中尚无档位，实现时在 src/styles/tokens.css 补一档（如 --fs-32）；数字必须 tabular-nums。热力图放大用 image-rendering: pixelated，保持像素边界。
