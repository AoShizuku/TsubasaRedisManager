设计要点
  • 三段式主区：Key 元信息头（类型 / 大小 / 编码 / slot）→ 类型工具条 → 数据表 → 值详情抽屉。抽屉可拖动高度，也可折叠成一行。
  • TTL 单独提出来做成控件，放在操作组最前面。它是唯一会自己变化、自带破坏性、又高频被修改的属性，混在灰色元信息里和 编码、slot 平级是不对的。倒计时在前端本地递减，不要每秒轮询服务端 TTL。完整规格见 doc/frontend/ttl.md。
  • 树里不显示 TTL：每个 key 显示 TTL 意味着每个 key 多一条 TTL 命令，类型色点已经付了一次 TYPE 的代价，再翻倍在大 keyspace 上不划算。做成设置项，默认关闭。
  • 两级搜索严格分离：侧栏搜索框做全局 Key SCAN（redis_start_search_keys），工具条上的筛选框只在当前 Key 已加载的字段内过滤。
  • SCAN 状态常驻状态栏：已扫描数 / 匹配数 / 进度条 / 停止按钮，对应 TaskProgressEvent；树的末尾另有一行「加载更多」，两处联动。
  • 值查看管线在抽屉里，而不是弹窗：文本 / JSON / Hex / Binary / MsgPack / 自定义格式化器，对应后端 CodecName 九种编解码，自动识别结果以绿色标签提示。
  • 标签栏的 + 是所有非 key 标签页的入口——CLI、Monitor、订阅、Key 浏览器、内存分析都从这个下拉菜单新建，菜单形态见 06-tree-modes.html。状态栏的内存读数 1.24 GB / 4 GB 可点击，直接打开按内存降序排的 Key 浏览器。
  • 只读连接在状态栏右下角持续显示红色锁标，写入类按钮（添加字段、保存、删除）在真实实现中应置灰。
  • 右键菜单覆盖 ref 文档要求的全部操作：复制、重命名、克隆、TTL、CLI、导出、删除；删除项用 Redis 红。
