# 视觉语言

覆盖：`src/styles/tokens.css`、`src/styles/base.css`（`.i`、`.mono`、`.num`）、`src/lib/icons.ts`、`src/components/ui/Icon.vue`、`src/components/ui/TypeDot.vue`、`src/components/ui/TypeChip.vue`、`src/stores/settings.ts`（`applyToDocument` 的字体替换）

颜色、尺寸、字号一律走 `tokens.css` 的变量，文档只写用途与变量名，数值以 `tokens.css` 为准。
`doc/fe_ref/` 的原型只表达视觉结果，规则以本文为准。

## 三条硬规则

这三条是整套视觉的骨架，任何新界面都要遵守。

### Redis 红只用于品牌与危险

Redis 红（`--brand`，危险语义同值的 `--danger`）只出现在四类地方：

- 品牌标记（应用图标，标题栏直接引用 `src-tauri/icons/icon.svg`）；
- 只读 / 生产标识（侧栏连接行的「只读」tag）；
- 删除类操作（菜单里的 `danger` 项、`variant="danger"` 的按钮）；
- 错误信息。

任何「强调」一律用蓝色 `--accent`：选中、焦点、主按钮、可点的计数、取消搜索、精确命中的徽标。
「快过期」这类需要醒目但不危险的状态用琥珀色 `--warn`。

理由：红色一旦被拿去做强调，真正的危险就不再显眼。终止一次搜索不丢任何数据，所以它的按钮是蓝的；
批量删除会，所以它是红的——颜色本身就在回答「这一下会不会出事」。

### 类型色只出现在三处

类型色（`--t-*`）只出现在：

1. 树 / 列表的圆点（`TypeDot`，包括 Key 浏览器的类型列）；
2. 标签页的圆点；
3. Key 元信息头的徽标（`TypeChip`）。

**表格内部不上色**，否则密集数据会退化成色块墙。STRING 用中性灰，因为它出现频率最高，
上彩色只会铺满整屏噪点。

唯一的补充是克隆对话框里的源 Key 徽标，理由见 [key-write-dialog](key-write-dialog.md)；
HLL 子形态不新增颜色，见 [hll-viewer](hll-viewer.md)。

### 等宽字体只给数据

key 名、字段名、值、分数、Stream ID、CLI 输出、十六进制用等宽；界面文案、按钮、标签、设置项一律界面字体。
边界与判据见下面「等宽字体的边界」。

## 图标

图标来自 `lucide-vue-next`，**在 `lib/icons.ts` 的 `ICONS` 里登记后再用**，模板里只通过 `Icon.vue` 按名字引用。
登记表用具名导入：`import * as icons` 会把整个图标库打进包里；集中登记也让全应用用到的图标一眼可数。

### 尺寸只有 12 和 16

Lucide 画在 24px 网格上。12（24 ÷ 2）和 16（24 × ⅔）落在整像素上；14 会让描边落在半像素上发虚。

| 尺寸 | 用于 |
|---|---|
| 16 | 工具条、操作按钮、菜单项 |
| 12 | 行内元数据、徽标内图标、树的箭头与图标槽 |

`Icon` 还接受 20，只给空状态里的大图标（如「该 Key 已不存在」），不进任何密集区域。

### 描边随尺寸变

Lucide 默认 `stroke-width: 2` 是按 24px 画布设计的，落到 12–16px 会又糊又重。
`strokeFor` 统一换算：12 → 1.5，16 → 1.75。不要在模板里另传描边。

`loader` 一律自转（`Icon.vue`）：它在多处被当作「正在忙」，不转就和普通图标没有区别。

## 等宽字体的边界

**数据用等宽，标注用界面字体。** 两者的对比是刻意的，不是疏漏。

| 等宽 | 界面字体 |
|---|---|
| key 名、namespace 段 | 连接名（用户起的标签，不是数据） |
| DB 名 `db0` | 按钮、菜单项、设置项 |
| Hash 字段名与值 | 类型徽标 `HASH` / `STRING` |
| List / Set 成员、ZSet 分数 | 编码标签 `JSON` / `GZIP` / `6 字段`（`.vtag`） |
| Stream ID 与字段值 | 状态文案、提示条、「不过期」这类状态词 |
| 十六进制、Base64 | 计数、耗时等纯数字标注 |
| CLI 输入与回包 | 表头 |
| 文件路径、命令模板 | |

**判据是「这段文字是不是 key 路径的一部分」，而不是「它在树的哪一层」。**
namespace 段是 key 路径的一部分——一个尾随空格都是真实字节——所以等宽；
连接名不是，它是用户起的标签，所以用界面字体。按层级判断的话，`user:profile:1001` 会在树里被拆成两种字形。

值预览里的 `.vtag` 故意保持界面字体：它是贴在数据旁边的标注，不是数据。

组件 CSS 里一律写 `var(--ff-mono-user)` / `var(--ff-ui-user)`，它们带着设置里的字体替换；
`--ff-mono` / `--ff-ui` 只是兜底栈。

### 中文不能穿透等宽栈

`--ff-mono` 的**末尾必须有中文字体**。常见的等宽字体一个带 CJK 的都没有，中文字符会逐个穿透整条栈
落到 generic `monospace`，由 WebView2 按语言挑默认等宽字体——Windows 简体中文下是**宋体**。
于是界面字体栈里的黑体与值列、key 名里的宋体并排出现，非常显眼；而中文值在 Redis 里太常见了，不是边缘情况。

CJK 本身是全角等宽，栈尾补黑体不破坏列对齐。中英文出自两份字体，宽度比不会是严整的 2:1，
但比宋体强得多，也不用往安装包里塞一份 CJK 字体。

设置里的等宽字体替换拼的是 `"用户选的字体", var(--ff-mono)`（`applyToDocument`），兜底继承这条栈。
所以**在设置里选一个纯拉丁的等宽字体不会让中文跟着变**——中文始终由栈尾的黑体接住。
想让中英文同源，得选带 CJK 的等宽字体（如 Maple Mono CN、Sarasa Mono SC），且要用户自己装。

## 数字对齐

会重绘或要纵向比较的数字必须配 `font-variant-numeric: tabular-nums`（通用类 `.num`），
否则数字宽度不一，重绘时左右抖、比较时错列：

- TTL 倒计时（每秒重绘）；
- ZSet 分数列（右对齐比较大小）；
- 表格里的索引、计数、大小、耗时；
- 树上的 namespace 计数；
- 状态栏与树底部行里随扫描跳动的数字；
- 勾选计数、大数字展示（`--fs-32`）。

## 字号档位

| 用途 | 令牌 | 颜色 |
|---|---|---|
| 正文、按钮、设置项（`body` 默认） | `--fs-13` | `--fg` |
| 表格内容、树节点、工具条、标签页 | `--fs-12` | `--fg` / `--fg-2` |
| 元数据、说明文字、状态栏 | `--fs-11` | `--fg-3` |
| 徽标、计数、快捷键 | `--fs-10` | `--fg-4` / 语义色 |
| 大数字展示（HLL 估算基数） | `--fs-32` | `--fg` |

**等宽数据比同层的界面字体小半号**，因为 JetBrains Mono 的视觉高度略大于 Inter，同号并排时等宽显得更大。
半号没有令牌，字面值写在用到的地方：`.dt .k` / `.dt .v`、树的 `.tname`、`.tab-name`、TTL chip 的 `.val`，
以及 Key 元信息头的 key 名（`.keyhdr h2`，等宽 600）。

界面字体与等宽字体都可以在设置 → 外观里替换，候选来自 `native_get_fonts`。

## 不做

- **用图标标识类型。** Redis 的类型没有公认图标，硬配只会增加认知负担；色点加元信息头的文字徽标已经足够。
- **14px 图标档。** 描边落在半像素上，是三档里最糊的一档，见「尺寸只有 12 和 16」。
- **barrel import 图标**（`import * as icons from 'lucide-vue-next'`）。会把整个图标库打进包里。
- **往安装包里塞 CJK 等宽字体。** 栈尾的系统黑体已经解决宋体问题，见「中文不能穿透等宽栈」。
