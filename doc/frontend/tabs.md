# 标签页

覆盖：`src/stores/tabs.ts`、`src/components/shell/TabBar.vue`、`src/components/shell/useShortcuts.ts`（`Ctrl B`、`` Ctrl ` ``、`Ctrl W`）、`src/components/main/MainArea.vue`（`renderKey`）、`src/components/shell/StatusBar.vue`（内存读数入口）、`src/components/cli/`、`src/lib/lineEdit.ts`

主区标签页有六种（`TabKind`）：key、Key 浏览器、CLI、Monitor、订阅、内存分析。
key 标签页从树或表格里点出来，其余五种都要有明确的来路。

## 入口：标签栏的 `+` 菜单

```
┌──────────────────────────────┐
│ 新建标签页                    │
│ ⊞  Key 浏览器         Ctrl B │
│ >_ 命令行             Ctrl ` │
│ ⚡ Monitor                   │
│ 🔔 订阅 (Pub/Sub)            │
│ ──────────────────────────── │
│ 📊 内存分析                   │
│ ⬆  导入 / 导出…               │
│ ──────────────────────────── │
│ 新标签页作用域  prod-east / db0 │
└──────────────────────────────┘
```

| 菜单项 | 快捷键 | 后端 |
|---|---|---|
| Key 浏览器 | `Ctrl B` | `redis_scan_keys`；分析模式下逐 key `redis_get_key_meta` |
| 命令行 | `` Ctrl ` `` | `redis_execute_cli` |
| Monitor | — | `redis_start_monitor` |
| 订阅 (Pub/Sub) | — | `redis_start_subscription` |
| 内存分析 | — | `redis_start_memory_analysis` |
| 导入 / 导出… | — | 还没有对话框，点了只给一句提示，见 [backlog](../backlog.md)「导入 / 导出没有界面」 |

菜单项与快捷键以 `TabBar.vue` 与 `useShortcuts.ts` 为准；快捷键同时登记在设置 → 快捷键那张表里，改一处要改两处。
焦点在输入框里时 `Ctrl B` 不抢键；`` Ctrl ` `` 照常生效。

**为什么是 `+` 菜单**：这是浏览器与 VS Code 的通用心智模型——`+` 就是「新建点什么」，用户不需要学；
而且它一次解决全部入口，不用为每个功能在界面上另找位置。

## 上下文入口：从树里带着上下文进去

光有 `+` 的问题是，Key 浏览器打开后是个全库视图，用户还得自己敲 MATCH 模式。顺的流程是从树里带着上下文进去：

| 触发 | 行为 |
|---|---|
| 右键 **DB 行** →「在 Key 浏览器中打开」 | 作用域 = 该 DB，MATCH `*` |
| 右键 **namespace**（含紧凑合并行的单个段）→「在 Key 浏览器中打开」 | MATCH 由该前缀拼出（`matchPatternFor`），如 `cache:page:*` |
| 右键 **DB 行** →「命令行」 | 在该 DB 上开 CLI |
| 点状态栏的内存读数 | 打开 Key 浏览器，打开分析模式并按内存降序 |

第二条让紧凑合并行的**分段命中**有了第二个用武之地：右键 `cache:page` 的 `cache` 段，就能把 `cache:*`
下的全部 key 拉进表格按内存排序。**树负责定位，表格负责分析，两者用同一个前缀串起来。**
前缀拼模式时要转义 glob 元字符，见 [key-tree](key-tree.md)「前缀生成模式必须转义 glob 元字符」。

第四条是廉价的高价值细节：内存读数是唯一一眼能看到「库有多大」的地方，让它可点，就是排查大 key 的最短路径。
注意分析模式是全局设置（`analysisMode`），从这里打开之后，之后新开的 Key 浏览器也是开着的。

## 预览页与驻留页

逛一遍 keyspace 会攒下二十个标签页，然后一个个关——这是最烦人的一段体验。按 VS Code 的 preview tab 模型解决：

| 动作 | 结果 |
|---|---|
| 单击树里的 key、Key 浏览器的一行、精确命中行 | **预览页**，标题斜体 |
| 双击树里的 key / 表格行 | 驻留页 |
| 双击标签页本身 | 预览页转正 |
| 右键 key →「打开」 | 驻留页 |
| 标签页右键 →「固定此标签页」 | 转正 |
| `+` 菜单、快捷键、右键菜单开的非 key 标签页 | 一律驻留 |

**全局只有一个预览页**：再单击别的 key 就地换内容，标签在栏里的位置不动。同一个（会话, key）已经开着时
直接切过去；这次是驻留打开就顺手转正。规则顺序见 `tabs.ts` 的 `open`。

双击不需要延时区分单双击：第一下已经开出预览页，`dblclick` 再把同一个标签转正。

预览页是就地换内容的（id 不变、key 变），所以主区的渲染 key 必须带上内容，不能只用标签 id，
理由写在 `MainArea.vue` 的 `renderKey` 旁。

### 写入即转正

对该 key 的写操作成功后（改值、改 TTL、重命名）自动转正。判据是「你对它动过手」：
既然改了，多半还要回来看，不该被下一次单击顶掉。

- **刷新按钮不算**——那只是看看。
- **批量操作不算。** 批量改的是一个范围，碰巧覆盖了开着的预览页时只刷新它的读数（keyspace 版本号），
  不动标签状态：把一个你没碰过的预览页转正会莫名其妙。

### 标签页右键菜单

关闭 / 关闭其他 / 关闭右侧 / 全部关闭，预览页额外多一项「固定此标签页」。中键点标签页也是关闭。

`Ctrl W` 关闭当前标签页，焦点在输入框里时不生效。不生效也要先拦下默认行为：webview 对 `Ctrl W` 的默认动作是关掉整个窗口。

## 标签标题带作用域

非 key 标签页的标题是 **`类型 · 作用域`**，如 `Key 浏览器 · db0`、`CLI · prod-east / db0`。
SCAN 本身按连接 + DB 隔离，同时开 `prod-east / db0` 和 `staging / db3` 两个浏览器是常见需求，标题不带作用域会分不清。

- 作用域取短形式（`shortScope`）：只开着一个连接时 `db0` 已经无歧义，省下宽度；开着多个连接时带上连接名；
  集群只有连接名。悬停提示给完整形式（`scopeLabel`）。
- 截断时先压作用域、保住类型词：`CLI · analytics-se…` 可读，`Key 浏览…` 不可读。标签宽度上限以 `layout.css` 的 `.tab` 为准。
- key 标签页的标题就是 key 名（等宽），作用域在悬停提示里。

## 新标签页继承当前作用域

`+` 菜单底部常驻显示「新标签页作用域 prod-east / db0」，避免在 A 连接的上下文里开出连到 B 连接的 CLI——
这类误操作在只读 / 生产库场景下代价很高，事后还很难发现。

作用域是侧栏当前选中项所属的会话，没有选中项时用活动会话（`sessions.selected` → `sessions.activeSessionId`）。
会话是 DB 级的（[backend/sessions](../backend/sessions.md)「会话是 DB 级的」），所以「选中项所属的会话」就是它最近的那个 DB。
快捷键走同一条规则。一个会话都没开时不新建，提示先在左侧打开一个数据库。

**作用域跟着当前标签页走**：切到某个标签页时，活动会话随之切到它的会话，属于别的会话的树选中项被清掉（`tabs.activate`）。
否则从 `prod / db0` 的 key 切到 `staging / db3` 的 CLI 之后，状态栏、搜索框、`+` 菜单的作用域还停在 db0，
下一个新标签页就开到错误的库上去了。这里只改作用域，不滚动、不展开、不动树。

## 只读会话下的差异

只读会话下 Key 浏览器、Monitor、订阅、内存分析**照常可用**——它们都是读操作。
`+` 菜单里置灰的只有「导入 / 导出…」，并在 title 里说明原因（该连接为只读模式），而不是默默不响应。

## CLI 标签页

CLI 是**请求 / 响应，不是 PTY**：`redis_execute_cli` 收一整行文本，回一个结果。
没有 ANSI、没有伪终端、没有行编辑器，所以界面是回显区 + 原生 `<input>`（`CliTab.vue`），
不是终端模拟器——用 xterm.js 还得自己实现一遍 readline，白费。

- 整行由后端解析，引号规则见 `services/cli.rs`；前端不拆参数。
- 借了 readline 手指记得最牢的几个键：↑ / ↓ 翻历史、Ctrl+W 删词（`lib/lineEdit.ts`）、
  Ctrl+L 清屏。这是为了顺手，不是要把行编辑器补回来。
- 回包里的值是 CLI 专用的 `RedisValue` 形状，功能路径的 `RedisText` 不在这里出现。
- 只读会话的拦截走 `services/readonly.rs` 的命令名匹配，见
  [backend/sessions](../backend/sessions.md)「只读属于会话」。
- 回显区是普通列表：不虚拟化，也没有条数上限，清屏才释放。

## 不做

- **为每个非 key 功能在界面上另找入口位置。** `+` 菜单一处解决，上下文入口只是带着前缀的捷径。
- **多个预览页。** 预览页的意义就是「随时会被下一次单击顶掉」，全局只有一个。
- **批量操作转正预览页。** 见「写入即转正」。
- **侧栏随当前标签页滚动定位。** 切标签页只同步作用域，不动树。
- **xterm.js / 任何终端模拟器**，理由见「CLI 标签页」。
