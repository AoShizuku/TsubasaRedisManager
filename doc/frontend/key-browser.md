# Key 浏览器

覆盖：`src/components/browser/KeyBrowserTab.vue`、`src/components/browser/useKeyAnalysis.ts`、`src/components/ui/VirtualTable.vue`（复选框列）、`src/stores/settings.ts`（`analysisMode`）

树形导航回答不了「哪些 key 最占内存」「哪些 key 马上要过期」。这类问题需要一张可排序的表。
分工由此清晰：**树形用来「逛」，表格用来「查」**。

```
Key                            类型     TTL          内存 ▼    编码
queue:mail:pending             LIST     不过期       6.14 MB   quicklist
events:audit                   STREAM   不过期       1.86 MB   stream
cache:page:home                STRING   00:04:12     842 KB    raw
…
lock:job:88213                 STRING   00:00:09     64 B      embstr
```

入口（`+` 菜单、DB / namespace 右键、状态栏内存读数）见 [tabs](tabs.md)「入口」与「上下文入口」。

## 放在主区，不放侧栏

表格是**主区的一个标签页**，与 Key 编辑器、CLI 并列。侧栏的宽度（`--w-side`）放不下「类型 / TTL / 内存 / 编码」四列，
硬塞的结果是每列都截断，排序也失去意义。

侧栏的「列表」模式是另一回事：它只是去掉缩进的 key 列表，见 [key-tree](key-tree.md)「列表模式」。

## 分析模式：成本必须显式化

TTL、内存、编码三列要对每个 key 额外取一次元信息，所以：

- 「分析模式」是工具条上一个**带成本提示的开关**，不是免费默认项（`analysisMode`，默认关闭，文案以 `KeyBrowserTab.vue` 为准）。
- 关闭时只有 Key 与类型两列，直接用 `redis_scan_keys` 已经带回来的类型。
- 打开时 `useKeyAnalysis` 对**全部已加载的 key** 取元信息，不只取可见行——排序需要全部已加载行的数据，
  只取可见行会排出一个随滚动位置变化的假顺序。打开开关会给已加载的行补齐，关掉则停止；进行中显示进度条与「停止」。
- 每个 key 一次 `redis_get_key_meta`，前端 8 路并发。这是前后端分层的一个现存例外，见
  [architecture](../architecture.md)「前后端分层」。
- 服务端不回 `MEMORY USAGE`（ACL、`rename-command`）时内存列为空，表格上方给横幅说明原因，并指向走后端任务的「内存分析」标签页。

## 排序只作用于已加载部分

点表头排序，内存列首次点击即降序。对百万级 keyspace 做全量排序需要先全量加载，界面不能假装已经排好了，
所以底部状态栏常驻「排序只作用于已加载的 N 个 Key」，扫描没完成时追加「扫描尚未完成」。

### TTL 列

「找出快过期的 key」在树里做不到，这是这张表存在的主要理由之一，所以 TTL 是一个可排序列。

- 升序时不过期的排在最后：`-1` 在数值上最小，语义上却是「最久」。没取到 TTL 的排在不过期之前。
- 读数是取元信息那一刻的快照，不倒数；要新读数就重新扫描。批量任务结束后表格会自己重扫（keyspace 版本号）。
- 查出来之后可以就地处理：勾选后批量续命或删除，见下面「多选」。

## 多选

表格多选是批量操作的入口之一，批量本身的规则见 [batch](batch.md)。

`VirtualTable` 的复选框列是可选的：`selectable` 打开，勾中的 rowKey 走 `v-model:selected`（`Set<string>`）。

- 复选框列在最左，宽度以 `table.css` 的 `.dt-check` 为准。**不上类型色**——表格内部不上色。
- **点行本身仍然是「打开预览页」**，复选框独占选择语义（复选框单元格 `@click.stop`）。两者混在一起的话，
  想勾第五行会先开一个标签页。同理，「当前行」（`selectedKey`）与勾选集合是两套状态，
  Key 浏览器传 `:selected-key="null"`。
- 表头复选框全选 / 全不选**已加载的行**，部分选中时显示半选（`aria-checked="mixed"`）。
- Shift 点选范围，从上一次勾选的位置算起；整个范围跟随这一下的方向——勾就全勾、取消就全消。
- 勾中的只可能是已加载的行：表格并不知道库里还有多少。所以操作条在计数旁写「仅限已加载的 N 行」，
  见 [batch](batch.md)「已加载不等于全部匹配」。
- 重新扫描时清空勾选（表换了一批，旧的勾选没有对应的行了），「加载更多」不清——那是同一批的延续。
  批量任务结束后 keyspace 版本号递增，表格随之重扫，勾选也就随之清空。

操作条 `.dt-bulkbar` 在有勾选时出现：「已选 N 个 Key」「仅限已加载的 N 行」、「设置 TTL…」「删除…」与「取消选择」。

- 它**插在表格与底部状态栏之间**，不是浮层。浮层要给表格补 `padding-bottom` 才不会盖住最后一行，
  插入一行天然不会；表格本来就是 `flex: 1`，挤一挤就好。
- 计数用 `tabular-nums`——勾选时数字一直在变，不加会抖。
- 类名用 `.dt-bulkbar`，不起 `.bar` / `.sel` 这种泛化名：泛化类名会和别处的同名类撞车。
- 只读会话下勾选照常可用，只有两个按钮置灰，见 [batch](batch.md)「只读」。

## 不做

- **把分析表塞进侧栏。** 放不下四列，见「放在主区，不放侧栏」。
- **分析模式默认开启。** 每 key 额外一次往返，大 keyspace 上不该是免费默认。
- **只分析可见行。** 排出来的顺序会随滚动位置变化，见「分析模式：成本必须显式化」。
