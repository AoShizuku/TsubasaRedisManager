六种类型的共同骨架
  • 元信息头永远在最上面，永远是同一套排布：key 名 + 类型徽标，下面一行是「规模 / 字节数 / 编码 / 位置」。规模的单位随类型变（字段、元素、成员、条），但位置固定，扫视成本最低。
  • TTL 是控件不是元数据，所以它在右侧操作组的最前面，而不是混在灰色元信息里。理由：它是唯一会自己变化、自带破坏性、且高频被修改的属性。四种状态见首页组件预览——不过期（中性灰）、倒计时（等宽 + tabular-nums，否则每秒重绘会抖）、即将过期（< 60 秒转琥珀色）、已过期（转 Redis 红，整个标签页切成"该 Key 已过期"）。切到 ZSET 标签可以看到点开后的编辑浮层。
  • 改 TTL 用浮层不用模态：高频低风险操作。三个选项直接对应 PERSIST / EXPIRE / EXPIREAT，底部永远显示换算出的绝对时刻和即将执行的命令——TTL 最常见的翻车就是单位和基准搞混。
  • 右上角操作组顺序固定：TTL · 分隔线 · 刷新 · 重命名 · 复制 · 分隔线 · 删除。删除永远在最后且是唯一的红色。
  • 工具条只放该类型特有的东西：List 是索引跳转与头尾插入，ZSet 是分数区间与排序，Set 是 SSCAN 模式，Stream 是 ID 区间与实时跟随。通用的视图切换一律靠右。
  • 值详情抽屉只在「单元格里塞不下」的类型上出现（Hash / List / Stream）。Set 和 ZSet 的成员本身就是短字符串，给它们加抽屉只会浪费高度。
  • 大 key 的处理是显式的：底部条永远写明「已加载 N / 总数」，配进度条和「再加载」按钮，而不是假装数据已经全在本地。
  • 类型色只用在三处：树/列表的圆点、标签页的圆点、元信息头的徽标。表格内部不再上色，避免密集数据变成色块墙。
  • CLI 复用同一套等宽字体与配色：整数绿、字符串红、nil 灰、错误用 Redis 红；每条回包右侧标注耗时。只读连接下写入命令在客户端直接拦截并给出中文错误。
